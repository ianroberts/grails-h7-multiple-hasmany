# Grails Hibernate 7 issue with more than one `hasMany`

This repository contains two Grails 8 applications to demonstrate an issue with Hibernate 7 and unidirectional `hasMany` associations (with no back-reference or `belongsTo` on the far side).  The `demo-h5` and `demo-h7` applications have identical domain class definitions and `BootStrap` logic, the only difference is that one was created from https://grails.apache.org/start/ with the Grails Data Implementation set to "Hibernate 5" and the other with "Hibernate 7".

## Setup

The apps model a situation from one of my real projects where I have a variety of different domain classes that can all have some form of "tags", and that have access controls in the form of a set of roles - the idea being that each item is accessible only to users who have one of the linked roles.  This is modelled as a pair of unidirectional `hasMany` associations - there is no `belongsTo` since the roles and tags do not belong to any particular parent, in the real app many different classes have a `hasMany` relation to `Role`.

```groovy
// Role.groovy
class Role {
  String authority
}

// Tag.groovy
class Tag {
  String name
  String description
}

// Item.groovy
class Item {
  String name

  static hasMany = [roles: Role, tags: Tag]
}
```

Typically one would create an `Item` and then use `item.addToRoles(...)` and `item.addToTags(...)` to associate the relevant entities.

## The issue

Both Hibernate versions model these domains the same way, with join tables `item_role` and `item_tag` to represent the `hasMany` associations.  However only Hibernate _5_ properly populates the join tables when flushing a session after an `addToRoles` or `addToTags` call - Hibernate 7 does not insert anything into the join table.

An alternative class with only _one_ `hasMany` relation:

```groovy
class UntaggedItem {
  String name

  static hasMany = [roles: Role]
}
```

persists its `addToRoles` calls correctly in both versions of Hibernate.  The combination that fails is only

- Hibernate 7, _and_
- more than one unidirectional `hasMany` in the same class

## Demo

To compare, do `./gradlew bootRun` in each of `demo-h5` and `demo-h7` in turn and observe the logs.  Both apps are set up with the `org.hibernate.SQL` logger enabled, so they log the SQL statements generated by Hibernate.  Observe that the `demo-h5` app properly inserts into both the `item_role` and `untagged_item_role` join tables, but in `demo-h7` only the "untagged" inserts are visible.
